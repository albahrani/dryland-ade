# Unsigned electron-builder releases with channel auto-update, launcher in the install directory

_Naming: the product is now Dryland ADE and the CLI binary is `dryland`; read `ade` in this ADR as `dryland` (launcher `bin\dryland.cmd` / `dryland`)._

The ADE is packaged with `electron-builder` and distributed through GitHub Releases (plus build-from-source via `pnpm`). Builds are unsigned in v1. Updates use `electron-updater` with the GitHub provider. We rejected a compiled standalone `ade` executable (it would duplicate the ~80 MB Electron runtime and still need a PATH entry) and a self-healing shim in a separate user directory (spreads files across the machine).

## Decisions

- **Targets**: NSIS (Windows x64, verified first), DMG (macOS arm64 + x64) and AppImage/deb (Linux x64). macOS and Linux are built in CI and verified best-effort.
- **Signing**: none in v1. The README documents the Windows SmartScreen and macOS Gatekeeper workarounds. Signing and notarization wait for demand.
- **Updates**: `electron-updater` with two channels, `latest` and `beta` (GitHub pre-releases), selectable in settings, default `latest`. Check at most once a day plus a manual "Check for updates"; download in the background and apply on next quit with a "restart to update" notice. Windows NSIS and Linux AppImage auto-update unsigned. macOS needs a signed app, so auto-update is disabled there and falls back to a notify-only "update available" link (limitation stated in the README). deb is notify-only.
- **`ade` launcher**: shipped inside the install directory (`bin\ade.cmd` on Windows, an `ade` script on macOS/Linux), forwarding to the bundled JS via `ELECTRON_RUN_AS_NODE`. It is replaced with the app on every update, so it always matches the app version. ADE-spawned PTYs get that directory prepended to `PATH`. Global PATH is opt-in: an NSIS checkbox (default off, removed by the uninstaller) on Windows, an `ade doctor` symlink into `~/.local/bin` on macOS/Linux, and `/usr/bin/ade` from the deb. Supersedes the "shim on PATH" wording in ADR 0002.
- **Shutdown**: a hard 2-second budget for both user quit and system shutdown (Windows kills unresponsive apps about 5 seconds after the shutdown request). Order: kill PTYs, release the ADE's own claims through `ade` (local file operations only), flush UI state. Network-backed claim releases (GitHub/GitLab) are never attempted at shutdown; stale-claim release covers them. Remaining steps are dropped when the budget runs out; atomic writes leave nothing half-written. Amended by ADR 0010: no claim is released and no tracker is written at quit or shutdown; the order is kill PTYs, then flush the session index and UI state.
- **Tests**: Vitest everywhere. The rule engine is table-driven snapshot-to-recommendation with a "why this next" assertion per rule; parsers use fixtures from real `.scratch` files. local-markdown backends run against temp git repos; GitHub/GitLab against recorded `gh`/`glab` JSON fixtures behind a process-runner interface (no live network in CI), plus a manual smoke checklist. Adapters get contract tests (launch command, pre-typed text, hook event to status mapping) using fake-CLI stub executables. One Playwright-for-Electron smoke test (launch, open fixture repo, see tickets tree) with a stub shell instead of a real agent. A parallel-claim test spawns N `ade ticket claim` processes against one repo and asserts exactly one winner.
