# The prompt set Dryland ships and tracking upstream releases

Type: grilling
Status: resolved
Blocked by: 08

## Question

Decide which prompts Dryland ships, how each derives from the unmodified upstream skills plus Dryland's own ideas, how agents reach tickets through dryland commands instead of files, and how a new upstream release is detected, diffed and adopted. Baselines: the upstream rules research, the engine-ownership decision and the storage decision.

## Answer

Decision: Dryland ships the workflow-bearing upstream skills as prompts (grilling, domain-modeling, grill-with-docs, wayfinder, research, prototype, triage, to-spec, to-tickets, implement, implement-spec, code-review, tdd, pr, retro, diagnosing-bugs, handoff) under their upstream names; setup-matt-pocock-skills is replaced by migrate and init, personal and in-progress skills are dropped, craft skills are not shipped. Derivation: a pinned unmodified upstream snapshot plus Dryland overlays generates each prompt; the build fails when an overlay anchor no longer matches. Overlays only swap tracker operations for dryland commands, add engine facts (gates, access-request protocol, expected write-time rejections) and add style rules (short structured prose, no paths, line numbers or bare ids); they never rewrite upstream judgement content. Agents reach state through the dryland CLI only, prose on stdin, no file paths, no MCP, no docs/agents tracker docs. Delivery: the engine syncs the generated prompt set into each agent CLI's skill folder in the worktree at every session launch, git-excluded via .git/info/exclude, with a version stamp and content hash so stale or hand-edited copies are overwritten; on-demand loading is kept in both CLIs; Claude Code --plugin-dir (session-only, outside the repo) is a later hardening option, Copilot CLI has no documented per-session route; the agent adapter may carry a per-CLI delivery field. Upstream tracking: snapshot pinned to an upstream commit with per-skill hashes; pnpm upstream:check (on demand and weekly in CI) lists changed, added and removed skills, shows diffs and reports broken overlay anchors; adoption is a maintainer act (bump snapshot, fix overlays, release, name the adopted upstream version in the CHANGELOG); new upstream skills are never added automatically. Overrides: expert feature; replace a prompt or append instructions, global and repo layers (repo override is a committed prose file), order built-in then global then repo; a stale replacement is flagged with a diff of built-in changes, appended text never; customized sessions show one badge with no per-prompt detail; the warning is dismissible and returns only when overrides change; engine gates apply regardless of prompts. Migration: removes shipped-set skills whose hash matches skills-lock.json, plus skills-lock.json and docs/agents issue-tracker.md and triage-labels.md; keeps skills outside the set and docs/agents/domain.md; a shipped-set skill with a differing hash becomes a repo override; installs nothing in the repo, the first session launch syncs. Dryland-native prompts without upstream base: unslop and a small tracker primer, not tracked against upstream, same override rules. Glossary: Prompt set, Overlay, Override added. Limits: per-prompt overlay list, CLI command vocabulary, lock and snapshot formats, doctor output and override file locations are left to the spec; one ADR (prompts derive from a pinned upstream snapshot through overlays) to be written with the ADR set; session-only skills for Copilot CLI and --resume behaviour in Claude Code are unverified.
