# Rules and workflow in the upstream skills

Baseline for extracting a deterministic workflow. Source: installed skills in `.agents/skills/<name>/SKILL.md` (mirrored to `.claude/skills`), byte-identical to `mattpocock/skills` per the 9-file spot check in `.scratch/mattpocock-ade/research/skills-inventory.md`; flow order from `ask-matt/SKILL.md`; tracker mapping from `docs/agents/issue-tracker.md`. Upstream was not re-fetched here; the catalog notes the aihero.dev category pages were unreachable (404).

Legend: **M** mechanical (code can check or enforce), **J** judgement (needs a model or human), **H** hybrid (mechanical precondition, judged content).

## Main flow (idea to ship)

```
grill-with-docs -> [prototype via handoff]? -> to-spec -> to-tickets -> implement | implement-spec -> (tdd, code-review) -> pr -> retro
on-ramps: triage -> ready-for-agent -> implement ; wayfinder -> (map clears) -> to-spec ; diagnosing-bugs -> retro
```

Precondition for tracker-touching skills: `setup-matt-pocock-skills` has written `docs/agents/*.md` (M: files exist).

## Per-skill

### grilling (+ domain-modeling, grill-with-docs)

| Aspect | Content |
|---|---|
| States | Design tree; rounds; session done when frontier empty |
| Artifacts | `GLOSSARY.md`, `docs/adr/NNNN-*.md` (created lazily, updated inline) |
| Hand-off | Out: decision reached, then to-spec or implement. Prototype branch via `handoff` |

| Rule | Kind |
|---|---|
| Ask the whole frontier per round; wait for answers before the next round | J |
| Each question numbered, with a recommended answer, phrased so "yes" accepts it | H (format M, content J) |
| Facts come from sub-agents, decisions from the user; never self-answer | J |
| Done only when the user confirms shared understanding; do not act before | J (confirmation event M) |
| Glossary updated inline when a term resolves; GLOSSARY holds no implementation detail | H |
| ADR only if hard to reverse AND surprising AND real trade-off | J |
| Glossary and ADR files follow GLOSSARY-FORMAT / ADR-FORMAT | M (format) |

### wayfinder

| Aspect | Content |
|---|---|
| Artifacts | Map (Destination, Notes, Decisions so far, Not yet specified, Out of scope); child tickets with type label; resolution comment; research notes |
| States | Ticket: open, claimed (assignee), closed; unblocked = all blockers closed; frontier = open, unblocked, unclaimed |
| Types | research (AFK), prototype (HITL), grilling (HITL, default), task (HITL or AFK) |
| Modes | Chart the map; work through the map |
| Hand-off | Map cleared to `to-spec`; research tickets to `research` skill subagents |

| Rule | Kind |
|---|---|
| Plan, don't do: tickets produce decisions, not deliverables (unless Notes override) | J |
| Only `wayfinder:<type>` labels on map and tickets; no triage labels | M |
| Map is an index: a decision lives once, in its ticket; map holds gist and link | H (shape M, gist J) |
| Claim first (assign) before any work | M |
| Blocking is native/explicit; frontier is computed | M |
| Never resolve more than one ticket per session, except research | M (count per session) |
| Resolve = post answer, close, append pointer to Decisions so far | M (sequence) |
| Closing a ticket graduates fog: new tickets created then wired in a second pass with real ids; graduated fog removed from Not yet specified | H (wiring M, graduation J) |
| Ticket sized to one ~100K-token session | J |
| Fog vs ticket: ticket if the question can be stated sharply, even if blocked | J |
| Out of scope: close the ticket, one line on the map, never in Decisions so far | H |
| No fog surfaced while charting: no map, ask the user | J |
| HITL ticket resolves only through live human exchange | J (type flag M) |
| Refer to tickets by title, never bare id | M (lint-able) |
| Charting fires research subagents on a throwaway `research/<name>` branch, pushed, no PR | M (this repo overrides: findings go to `.scratch/<effort>/research/`) |
| Concurrent sessions: expect parallel edits to the tracker | M (needs locking or CAS) |

### triage

| Aspect | Content |
|---|---|
| States | Category: `bug`, `enhancement` (exactly one). State: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` (exactly one). Unlabeled enters `needs-triage`; `needs-info` returns to `needs-triage` on reporter reply; maintainer may override |
| Artifacts | Agent brief comment, needs-info notes comment, `.out-of-scope/<concept>.md`, AI disclaimer line |
| Hand-off | `ready-for-agent` to `implement` |

| Rule | Kind |
|---|---|
| Exactly one category and one state role per triaged issue; conflicting states are flagged, not resolved | M |
| Allowed transitions (above); unusual ones flagged and confirmed | M |
| Every comment starts with `> *This was generated by AI during triage.*` | M |
| Attention buckets: unlabeled, `needs-triage`, `needs-info` with reply since last notes; oldest first | M |
| PR is an issue with code; discovery lists only external PRs; named PR always triaged | M (author test) |
| Redundancy check and prior-rejection check (`.out-of-scope/`) before recommending | J |
| Recommend, then wait for maintainer direction | J (wait event M) |
| Verify the claim (reproduce bug, check PR diff) before grilling | J |
| Grill via grilling + domain-modeling when under-specified | J |
| `ready-for-agent`: agent brief with Category, Summary, Current, Desired, Key interfaces, Acceptance criteria, Out of scope | H (sections M, content J) |
| Brief is durable: no file paths, no line numbers, behavioural not procedural | H (path/line regex M, rest J) |
| `needs-info` template with established and still-needed lists; questions specific | H |
| `wontfix` variants: already implemented (point to code, no KB entry); rejected bug (explain, close); rejected enhancement (write `.out-of-scope/`, link, close) | H (side effects M, classification J) |
| Quick override: trust the maintainer, confirm, apply; ask whether to write a brief | M |
| Do not triage `to-tickets` output (already agent-ready) | M (origin flag) |
| Resume: read prior notes, do not re-ask resolved questions | J |

### to-spec

| Aspect | Content |
|---|---|
| Artifacts | `spec.md` (Problem Statement, Solution, User Stories, Implementation Decisions, Testing Decisions, Out of Scope, Further Notes), labelled `ready-for-agent` |
| Hand-off | To `to-tickets` |

| Rule | Kind |
|---|---|
| No interview; synthesize the conversation only | J |
| Use glossary vocabulary; respect ADRs | J |
| Propose test seams (prefer existing, highest, ideally one) and confirm with the user before writing | J (confirmation M) |
| Template sections present, in order | M |
| No file paths or code snippets (exception: prototype snippet encoding a decision) | H (path regex M) |
| Long, extensive user story list, `As an <actor>, I want a <feature>, so that <benefit>` | H (format M, coverage J) |
| Published with `ready-for-agent`, no further triage | M |

### to-tickets

| Aspect | Content |
|---|---|
| Artifacts | One file per ticket `.scratch/<feature>/issues/NN-slug.md` (What to build, Blocked by, Status, acceptance criteria), numbered from 01 in dependency order; or one issue per ticket with native edges |
| States | `ready-for-agent`; frontier = blockers all done |
| Hand-off | To `implement` (per ticket) or `implement-spec` (whole graph) |

| Rule | Kind |
|---|---|
| Tracer-bullet vertical slices through every layer; each demoable alone | J |
| Each slice fits one fresh context window | J |
| Prefactoring first | J |
| Every ticket declares blocking edges ("None" if free); graph must be acyclic | M |
| Wide refactor exception: expand, migrate batches, contract (blocked by all migrates); optional integration branch plus final verify ticket | J (structure of edges M) |
| Quiz the user on granularity, edges, merges; iterate to approval | J (approval event M) |
| Local: one file per ticket, never combined; numbering blockers-first | M |
| Real tracker: publish in dependency order so edges reference real ids; sub-issue of source issue | M |
| Apply `ready-for-agent` | M |
| Do not close or modify the parent issue | M |
| No file paths or code snippets (prototype exception) | H |

### implement

| Aspect | Content |
|---|---|
| Artifacts | Commits on the current branch; code-review report |
| Hand-off | In: ticket ref; calls `tdd`, then `code-review` |

| Rule | Kind |
|---|---|
| State the ticket title before starting; ask if ref ambiguous | M (echo) / J |
| Use `tdd` at pre-agreed seams where possible | J |
| Typecheck regularly, single test files regularly, full suite once at end | H (full-suite-green gate M) |
| Call `code-review` when done | M (sequence) |
| Commit to the current branch | M |

### implement-spec

| Aspect | Content |
|---|---|
| Artifacts | Integration branch; per-ticket worktrees and branches; draft PR (if tracker closes via PRs); exploration notes outside the repo |
| States | Task graph; frontier changes as tickets complete |
| Roles | Orchestrator, exploration subagent, implementer subagents (background, own worktree), merger subagent |

| Rule | Kind |
|---|---|
| Tickets are a graph, not a list; dispatch whole frontier concurrently | M |
| Pass context pointers (spec, tickets, notes, commits), not copies | J |
| Draft PR opened after the first merge (branch needs commits ahead), marked as closing spec and tickets | M |
| Implementer: worktree based on integration tip (reset if not), uses `tdd`, merges integration tip in before reporting done | M |
| Merger subagent merges completed work into the integration branch | M |
| After all tickets: one `code-review` on the integration branch; all fixes in one implementer | M (sequence) / J (fixes) |
| Finish: mark draft PR ready, else resolve each ticket per tracker and report the branch | M |
| Clean up worktrees | M |

### code-review

| Aspect | Content |
|---|---|
| Artifacts | Report with `## Standards` and `## Spec`, one-line summary |

| Rule | Kind |
|---|---|
| Fixed point supplied or asked for; must resolve (`git rev-parse`) and diff non-empty before sub-agents | M |
| Diff is three-dot `<fixed>...HEAD`; commit list `<fixed>..HEAD` | M |
| Spec source order: issue refs in commit messages, user path, spec file under docs/specs/.scratch matching branch, else ask; none means skip Spec axis | H |
| Standards sources: every documented-standards file; `CODING_STANDARDS.md` and `CONTRIBUTING.md` mandatory if present | M |
| Smell baseline (12 Fowler smells) always applied; always judgement; repo standard overrides; skip what tooling enforces | J |
| Two sub-agents, parallel, foreground; reports under 400 words | M (structure) |
| Axes never merged or reranked; summary gives count and worst issue per axis | M |
| Spec findings: missing/partial, scope creep, wrong; quote the spec line | J |

### tdd

| Rule | Kind |
|---|---|
| Test only at pre-agreed, user-confirmed seams | H (confirmation recorded M) |
| Red before green; failing test first | H (test fails first checkable M) |
| One seam, one test, one minimal implementation per cycle; vertical not horizontal | J |
| Refactoring is not part of the loop (belongs to review) | J |
| Anti-patterns: implementation-coupled, tautological tests | J |
| Test names use glossary vocabulary | J |

### pr

| Rule | Kind |
|---|---|
| Body has Summary, Evidence, Merge Danger sections in order | M |
| Summary: smallest visual (pseudocode, call tree, component tree, file tree, mermaid, diff) | J |
| Evidence: before and after; screenshots S-tier, test output A-tier | H (presence M) |
| Merge Danger: Door is one-way or two-way; Blast Radius one word | H (field presence and enum M, call J) |
| No preamble; glossary language | J |
| Model-invoked automatically when writing a PR body | M (trigger) |

### retro

| Rule | Kind |
|---|---|
| Call `writing-for-agents` first; read session logs (default current session) | M |
| Candidate categories: navigation, automated checks, coding standards, global AGENTS.md, tool economy, no-ops, information access | J |
| Classify violation: mechanical gets a deterministic check (lint rule, hook, CI job); judgement goes to `CODING_STANDARDS.md` | J (the classification itself is this table) |
| No guardrail in the repo is itself a finding | M (detect hooks/CI) |
| Review agent imposes standards, not implementation agent; AGENTS.md only for navigation pointers | J |
| Present candidates by severity | J |

### Supporting skills (hand-off edges only)

- `research`: background agent, primary sources, one Markdown file in the repo's existing notes location (J content, M location). Called by wayfinder research tickets.
- `prototype`: throwaway code answering a design question; branches LOGIC.md/UI.md; linked as an asset. Bridged by `handoff` both ways.
- `handoff`: compact conversation into a doc in the OS temp dir, with a "suggested skills" section; no duplication of artifacts, redact secrets (redaction J).
- `diagnosing-bugs`: feedback loop first, no theorising before a red command; ends with regression test; then `retro`.

## Cross-cutting findings

1. **State lives in a small set of enumerable fields**: ticket status (open, claimed, resolved), triage role (5 states, 2 categories), blocking edges, ticket type (4), map sections (5), spec sections (7), PR sections (3). All are checkable by code.
2. **Almost every skill has a mechanical shell and a judgement core**: sequence, required sections, one-of enums, ordering, "do X before Y", confirmation events are M; sizing, slicing, fog-vs-ticket, content of briefs and gists, smells, recommendations are J.
3. **Ordering rules (the engine's core)**: claim before work; one ticket per session (research excepted); resolve = answer, close, index; blockers before dependents; seams confirmed before tests; Standards and Spec reviewed separately; user approval before publishing tickets and before acting after grilling; code-review after implement; PR draft after first merge.
4. **Human gates** (events the engine must wait on): end of grilling round, "shared understanding" confirmation, seam confirmation (to-spec, tdd), ticket breakdown approval (to-tickets), maintainer direction after triage recommendation, HITL ticket resolution.
5. **Format rules already lint-able**: AI disclaimer line, one category plus one state label, no file paths or line numbers in specs, tickets and briefs, tickets referred to by title, template section presence, `Blocked by` present, numbering order.
6. **Tracker-specific operations are indirected** through `docs/agents/issue-tracker.md` (publish, fetch, claim, resolve, blocking, frontier); the Dryland CLI already implements these for local markdown, which is the seam where an engine owning state would sit.
7. **Upstream contradictions with this repo's setup**: wayfinder's throwaway pushed `research/<name>` branch vs this map's `.scratch/<effort>/research/` convention and "no throwaway branches"; wayfinder's issue-as-map vs a local `map.md`; upstream labels `wayfinder:*` vs `Type:` and `Status:` lines.
8. **Gaps and unverified**: upstream not re-fetched this session (installed copy trusted on the earlier spot check); aihero.dev category pages unreachable; versions drift (changelog: v1.3 on 2026-10-05 added implement-spec, pr, retro, GLOSSARY.md) so a release-tracking rule is needed (see map Notes).
